# Animations Start Over

Frame-by-frame 2D combat characters for an RPG-style game. Gemini draws the poses, scripts cut and align them into strips, a small tool marks where each hand holds each weapon, and a test page plays everything: movement paths, weapons, a lightning skill. State as of 2026-11-01. This file is the overview; the details are in `docs/`.

**Decisions so far**
- Characters are frame-by-frame strips; the weapon is a separate layer (the hands in the art are empty fists), so one set of art works for any weapon.
- Skill effects (lightning, projectiles, auras, hit sparks, shake, damage numbers) are built in code and tuned by eye, not drawn as frames.
- Game engine: Pixi.js is recommended for the battle scene. The strips and the json files are engine-neutral, and the test page is the working prototype and the spec. Nothing is locked in.
- Only animations that travel (attack, dodge) get a movement path. Hit and death play in place.
- Fighters are drawn at 80% of their first size (`--unit-scale` in the page's CSS, 2026-11-01) and the stage has one fixed headroom for every character (`HEADROOM`, 0.788 character widths = 145 px at full size: 1.1 at first, then 0.935 because it looked too empty at the top, then 0.788 after comparing pictures on a phone), so the stage is the same height for the warrior and the mage; the gap between the fighters went from 33% to 45% of the stage width. ## Quick start

Press Play for a whole fight (the "Scenario" box picks win or lose), or use the preview buttons: "Preview attack", "Preview dodge", "Preview skill". The panels below the stage hold the path editor, the skill effect settings, the pack slots and the weapon switches.

**Add or replace an animation:** put the new strip, its `.hand-anchors.json` and (if it has one) its `.placement.json` in the animation's folder, then run

```
python source/tools/build.py
```

and copy `source/dist/warrior-vs-goblin-test.html` over `warrior-vs-goblin-test.html` in this folder. To try a strip without rebuilding, use its pack slot in the page and pick the strip and its `.hand-anchors.json` together (Ctrl-click both): hand marks are matched to a pack by file name (`armored_idle_strip.png` uses the animation `armored_idle`).

**Everything about making animations** (prompting Gemini, cutting, marking hands, paths, effects) is in `docs/PLAYBOOK.md`.

## The frame standard (every strip must follow it)
- Frames are 512 px wide, side by side in one row. Normal frames are 512 x 512. Taller frames (jumps, hops) add headroom above the same ground line: 512 x 640.
- The character is about 408 px tall when standing, with one shared scale for the whole animation.
- The ground line is 42 px above the bottom edge of every frame (y = 470 of 512, y = 598 of 640). Grounded frames rest their feet on it.
- The warrior's idle stance: rear heel at x = 160, front toe at x = 426, middle of the feet at x = 293. Every grounded animation is lined up with these, so the character does not slide when the animation changes. (Older notes said "front toe 336"; that was wrong. See the known issues.) A new character gets its own numbers from its own idle: `python source/tools/check_strip.py <idle strip>` prints them.
- Transparent PNG, no weapon in the hands, no text, borders or shadows.

## Known issues and ideas
- **The jump attack strip stands about 88 px left of the idle.** It was cut with the toe at x = 336 (the wrong number above), so its first frame sits left of the idle stance and the character steps left when the attack starts. The paths and hand marks were tuned with it that way. Fixing it means re-cutting with `--toe-x 426`, shifting each frame's hand marks by the same amount, and re-checking the path. The dodge had the same problem and was fixed on 2026-10-29 that way (the art moved 45 px right, and every hand mark moved by the same 45 px).
- The test page has fixed slots (idle, attack, hit, death, dodge) and one warrior against a goblin placeholder. It cannot yet play arbitrary named animations or two real characters.
- The hand drawn over a grip is found by skin colour near the mark, so gloves and armoured hands fall back to a plain disc. A proper separate hand layer is still an idea (`docs/DEV_NOTES.md`).
- Gemini cannot keep left and right arm identity between frames. The workaround is the per-frame front or behind mark in the hand tool, not fighting the generator.
- Ideas not built: a frame picker (choose the best frame per slot across several generations), a viewer that plays any animation by name, hit-stop (a short freeze at impact), sound.
